# Decision log — spec-stepped-buzz-sweep

## 2026-06-22 — create

Source: this session's diagnosis of the non-phase buzz freeze + the mainline
comparison. No prior SPEC at this folder; create. Related: the smooth-sweep
generator this replaces-for-pulse is specced in
[[spec-xdirect-buzz-phase-scheduling]].

Findings that drove it: the STEP/DIR exact-crossing solver is ~37× costlier per
emission for a chirp than a tone (offline-measured: 640 ns vs 17 ns), because a
chirp has no closed-form crossing inverse and falls back to scan+bisection per
crossing. `main` (pre-rewrite reference) sidesteps this entirely — it never
sweeps smoothly; `VibrationPulseTestGenerator.gen_test()` emits fixed-frequency
half-oscillations and steps the frequency a notch per half-cycle, played as
regular moves. The fix mirrors that: sweep = loop of single-frequency tones,
each `mu = 0` → closed-form on both XDIRECT and STEP/DIR.

**Pass 1 — Coherence.** Five capabilities, each intent+success. CAP-4 ("reuse the
single-freq buzz, loop is the only new logic") leans toward mechanism but states a
testable structural property, not an implementation recipe; the HOW (host vs MCU
loop) is deliberately left to an open question. Constraints bend design: "each
segment mu=0 / no chirp for the default sweep" rules out the path that caused the
freeze. Four explicit non-goals. Success signal is concrete and bench-observable
(non-phase sweep plays straight through, no starvation forensics, shaper matches).

**Pass 2 — Preservation.** Load-bearing claims all landed: chirp→scan→freeze
causal chain (Why); 37× cost (Why + CAP-2 success); mainline staircase as the
model (Why + CAP-1 + constraint); single-frequency-buzz reuse (CAP-4 + constraint);
both-axes routing (CAP-3 + constraint); calibration-resolution adequacy (CAP-5 +
assumption). No load-bearing drop. Wrapper-only content (the /bmad-spec ceremony)
carries nothing to preserve.

Four open questions logged — loop location (host vs MCU), inter-segment continuity
(gaps/ramps vs seamless), per-segment duration, and whether the smooth XDIRECT
chirp survives as an alternate mode. These are the real design forks the "easy
loop on top" framing leaves unresolved; none blocks starting, but the
continuity/loop-location pair determines whether this is a trivial host loop or a
small MCU sequence change.

Verdict: coherent and preservation-complete. Ready for implementation once the
loop-location / continuity questions are settled.

## 2026-06-23 — open questions resolved (dderg)

dderg settled all four forks in one line: "mcu side. we could leave [the smooth]
phase [chirp] sweep, but I'd rather keep things simple. less code is always
better." Resolution:

- Loop location → **MCU-side**. One command, generator steps frequency at segment
  boundaries. Not a host loop.
- Continuity → **seamless**, forced by the mechanism rather than added as a feature.
  Reading mainline's `gen_test()` closed the question: it steps frequency at every
  half-period **turning point** (velocity zero), via abutting constant-accel
  segments — there is no cross-fade because there is no discontinuity to fade. Port
  the same rule: hold the carrier frequency constant within a segment, step it (and
  the `f_start/f` amplitude taper) only at a turning point, one envelope for the
  whole band.
- Per-segment duration → **one half-period** (mainline's resolution); increment
  `hz_per_sec * segment_seconds`.
- Chirp → **replaced, not kept** ("less code is always better"). This **flips the
  original non-goal** "not removing the MCU's chirp (`mu`) support": with no curve
  setting `mu != 0`, the continuous-chirp path and its per-crossing scan/bisection
  machinery (`scan_next_change`, `refine_crossing`/`refine_extremum`, the `amp_eff`
  *taper-rate*/`omega_inst` *slew* terms) become dead and are removed.

Architecture chosen for implementation: **single continuous-phase generator with
piecewise-constant frequency** (not engine-sequenced re-arms). Rationale: the
XDIRECT generator already segments per half-cycle at turning points and recomputes
its grid density there — extending it to also step `omega`/amplitude at the turn is
a local change. Engine-re-arm-per-segment (the literal "loop on top") would re-arm
~10^4 times for a full band and needs the generator to support amplitude-continuous
chaining anyway, so it is more moving parts for the same result. This refines CAP-4:
the per-tone *math* is reused unchanged; the generator gains a turning-point
frequency step. The within-segment `mu = 0` closed-form (STEP/DIR) and
`time_at_phase` reduction (XDIRECT) are what keep both axis types off the scan.

Open sub-point carried into implementation: at a turning point the carrier is at a
displacement extreme `±A`, so stepping the amplitude taper there moves the extreme
by `ΔA = A * (f_k/f_{k+1} - 1)` — at `hz_per_sec ~ 1` the per-half-period `Δf` is
~milli-Hz, so `ΔA` is sub-microstep and rounds into the normal step grid; not a
jolt. Verify on the bench capture that the staircase spectrum is clean.

## 2026-06-23 — scope narrowed to pulse-only; phase chirp retained (dderg)

Two clarifications from dderg reshaped the architecture mid-design:

1. "we don't loop the regular buzz because this adds an awkward condition, it's a
   separate function then." → The sweep is its OWN generator, not the fixed-tone
   path gated by a `swept?` flag. Looping/re-arming the single-tone buzz (and the
   per-segment-envelope problem that comes with it) is the awkwardness avoided.

2. "if it is a separate function then it makes sense to keep the phase stepped
   behavior as it is now. since it's working." → The XDIRECT/phase chirp is NOT
   touched. It never root-solves `position = gridline` (the freeze cause), so the
   chirp is already cheap there. The new staircase is **pulse-only**.

This REVERSES the prior-session lean "chirp replaced everywhere / one mechanism /
no fork." New shape: the per-axis-mode routing forks deliberately — phase →
unchanged continuous chirp, pulse → new staircase generator. The `mu` machinery
survives (XDIRECT consumes it); only the pulse path stops constructing `mu != 0`.
Net: a smaller, more surgical change than the both-paths rewrite, at the cost of
"less total code" — accepted, because not entangling two working things wins.

Implementation shape settled with it: the pulse generator is closed-form per
segment across the flat top (step `omega`/amp at each turning point), and HOLDS
frequency constant through the two ramp ends (`freq_start` in, `freq_end` out) so
the existing constant-frequency tone solver — which already does the time-varying
ramp amplitude for a fixed tone — covers onset/offset with no new ramp math. So
the only genuinely new code is flat-top segment sequencing. Mainline's no-envelope
accel construction can't be copied verbatim (a raw sine starts at peak velocity →
jolt from rest), which is why the global ramp stays.

Spec re-synced: Why (resolved-shape ¶), CAP-3, CAP-4, Constraints, Non-goals,
Assumptions, Resolved-decisions all updated from "replace everywhere" to
"pulse-only separate generator, phase chirp retained."
