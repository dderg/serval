# EtherCAT Servo-Axis Integration — Part A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any motion axis be driven by an EtherCAT servo (via the existing `kalico-ethercat-rt` endpoint) instead of a stepper, reaching klippy `ready` with no commanded motion.

**Architecture:** A two-tier klippy config surface (`[ethercat_node <name>]` connection + `[servo_<axis>]` device) declares the servo axis; the Rust bridge instantiates an `EtherCatNode` (`UnixNativeConn`) alongside the serial `StepperMcuNode`s and routes the servo axis's curve plan to it. **Bridge axis-routing for Part A is hardcoded (X → node, Y/Z → steppers)** — the proper data-driven `init_planner` refactor is explicitly deferred to a separate branch (operator decision, 2026-05-31); see Task 3. A no-hardware stub server stands in for the drive so the whole path is testable powered-down.

**Tech Stack:** Rust (`rust/motion-bridge`, `rust/kalico-ethercat-rt`, PyO3), Python (`klippy/`), cargo + pytest. Bench: Pi 3B, A6-EC servo on `eth0` (powered OFF until the final operator-supervised step), Linux-process stepper MCU already at `ready`.

**Source spec:** `docs/superpowers/specs/2026-05-31-ethercat-servo-axis-integration-design.md`

## Critical context the implementer MUST know

**This is a fork of Kalico (Klipper lineage). The motion path is NOT stock Klipper.** Steps are generated by a Rust runtime over a "kalico-native" wire protocol, not the C trapq. Key facts gathered from the code:

- **Bridge entry is `init_planner` (`rust/motion-bridge/src/bridge.rs:1847`)**, currently hardcoded to two serial MCUs. It builds `mcu_configs: Vec<McuAxisConfig>` at `bridge.rs:1909` as a fixed `[{octopus_handle: X,Y, kin=corexy}, {f446_handle: Z, kin=cartesian}]`. `McuAxisConfig { mcu_id, axes: Vec<usize>, kinematics: u8, caps }` is defined in `rust/motion-bridge/src/dispatch.rs:44`. **Part A keeps this hardcoded** and adds one more hardcoded entry for the EtherCAT node (Task 3); the generic data-driven version is a separate-branch task the user owns.
- **Klippy `_init_planner` (`klippy/motion_toolhead.py:831`)** finds bridge MCUs by name (`octopus="mcu"`, `f446="mcu z"`; if one MCU, `f446 = octopus`) and passes the two handles to `init_planner`, then calls `_configure_axes_per_mcu(bridge_mcus)` (`motion_toolhead.py:901`).
- **`claim_mcu(label, serial_path, baud)` (`bridge.rs:549`)** registers an MCU into `self.mcus: HashMap<u32, McuConnection>` and returns the `mcu_id`. `McuConnection` (`bridge.rs:80`) has `serial_path`, `host_io: Option<Arc<KalicoHostIo>>`, `kalico_native_supported: bool`, etc. `attach_serial` (called from `klippy/mcu.py:1599` during `MCU._connect`) opens the serial port + identify and sets `host_io` + `kalico_native_supported`.
- **The node-build + dispatch live inside `init_planner`** (`bridge.rs:1953` host_ios, `:2006` dispatch_ios, `:2109` `nodes`, `:2214` dispatch closure). `nodes: HashMap<u32, Arc<dyn MotionNode>>` is built only with `StepperMcuNode`. The dispatch closure at `bridge.rs:2236` does `dispatch_ios.get(&plan.mcu_id) ... None => continue` — this silently skips any node not in `dispatch_ios` (i.e. an EtherCAT node). The existing comment at `bridge.rs:2230` prescribes the fix.
- **`EtherCatNode::new(conn: Arc<UnixNativeConn>, credit: Arc<CreditCounter>, slot_pool: Arc<SharedSlotPool>)` (`rust/motion-bridge/src/motion_node.rs:80`)** already exists; `MotionNode::load_and_push` is implemented for it. `UnixNativeConn::connect(path)` (`rust/kalico-host-rt/src/unix_native_conn.rs:44`) exists and implements `NativeCall`.
- **`kalico_native_for_plans` (`bridge.rs:1979`)** must be `true` for a plan's `mcu_id` or the plan is skipped at `bridge.rs:2219`.
- **`kalico-ethercat-rt` endpoint** (`rust/kalico-ethercat-rt/src/bin/kalico-ethercat-rt.rs`) is `required-features = ["hw"]`. The lib (`server.rs`, `wire.rs`, `curves.rs`, `scale.rs`, `clock.rs`) builds without `hw`; `ffi.rs` and `build.rs` linking are `hw`-gated. FFI calls in main() are isolated: `ec_rt_bringup` (init), `ec_rt_cycle`/`ec_rt_set_target_position`/`ec_rt_get_position_actual` (loop), telemetry getters, `ec_rt_disable`/`ec_rt_shutdown` (teardown).

- Bench firmware/host flow: commit → push → pull on Pi → build on Pi. Never scp binaries/source to bypass git. Build with `make -j$(nproc)` on the Pi.

```rust
//! kalico-ethercat-rt-stub: no-hardware endpoint. Binds the kalico-native
//! socket and answers Identify/LoadCurveCubic/PushSegment/ResetCurvePool,
//! exercising the curve store + sampler, but drives NO hardware. For drive-off
//! integration testing (the real endpoint is `required-features = ["hw"]`).

use std::thread::sleep;
use std::time::Duration;

use kalico_ethercat_rt::clock::monotonic_ns;
use kalico_ethercat_rt::curves::{ChannelTrack, CurveStore};
use kalico_ethercat_rt::server::FrameServer;
use kalico_ethercat_rt::wire::{
    Command, identify_response_frame, load_curve_response_frame,
    push_segment_response_frame, reset_pool_response_frame,
};
use kalico_protocol::messages::PushSegment;

fn arg_val(args: &[String], key: &str) -> Option<String> {
    args.iter().position(|a| a == key).and_then(|i| args.get(i + 1).cloned())
}

fn pick_handle(seg: &PushSegment, sel: &str) -> u32 {
    match sel {
        "y" => seg.handle_y,
        "z" => seg.handle_z,
        "e" => seg.handle_e,
        _ => seg.handle_x,
    }
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    let socket = arg_val(&args, "--socket")
        .unwrap_or_else(|| "/tmp/kalico-ethercat.sock".into());
    let handle_sel = arg_val(&args, "--handle").unwrap_or_else(|| "x".into());

    let store = CurveStore::new();
    let mut track: Option<ChannelTrack> = None;
    let mut pending: Option<(u32, u64, u64)> = None;

    let mut server = FrameServer::bind(&socket).expect("bind socket");
    eprintln!("ec-rt-stub: socket {socket}, handle {handle_sel} (NO HARDWARE)");

    loop {
        for cmd in server.poll_commands() {
            match cmd {
                Command::Identify { correlation_id, proto_version } => {
                    server.respond(&identify_response_frame(correlation_id, proto_version));
                }
                Command::LoadCurve { correlation_id, msg } => {
                    match store.load(msg.slot_idx, msg.piece_count, &msg.pieces_bytes) {
                        Ok(h) => server.respond(&load_curve_response_frame(correlation_id, 0, h)),
                        Err(e) => {
                            eprintln!("ec-rt-stub: load err {e:?}");
                            server.respond(&load_curve_response_frame(correlation_id, -1, 0));
                        }
                    }
                }
                Command::PushSegment { correlation_id, msg } => {
                    let h = pick_handle(&msg, &handle_sel);
                    pending = Some((h, msg.t_start, msg.t_end));
                    server.respond(&push_segment_response_frame(correlation_id, 0, msg.id));
                }
                Command::ResetPool { correlation_id } => {
                    store.reset();
                    track = None;
                    pending = None;
                    server.respond(&reset_pool_response_frame(correlation_id, 0));
                }
                Command::Unknown { kind_raw, .. } => {
                    eprintln!("ec-rt-stub: ignoring kind 0x{kind_raw:04x}");
                }
            }
        }
        let now = monotonic_ns();
        if let Some((h, t0, t1)) = pending.take() {
            track = Some(ChannelTrack::arm(h, t0, t1));
        }
        if let Some(tr) = track.as_mut() {
            let _ = tr.sample(&store, now); // exercise sampler; discard counts
            if tr.is_done(now) {
                track = None;
            }
        }
        sleep(Duration::from_millis(1));
    }
}
```

```rust
/// Register an EtherCAT node with the bridge. Like `claim_mcu` but the
/// transport is a same-host Unix socket (the kalico-ethercat-rt endpoint),
/// not a serial port. Returns the opaque handle. The socket is connected and
/// the node is marked kalico-native during `init_planner` (no separate
/// attach_serial step). Returns the mcu_id handle.
#[pyo3(signature = (label, socket_path))]
fn claim_ethercat_node(&self, label: &str, socket_path: &str) -> PyResult<u32> {
    let mut router = self.router.lock().unwrap_or_else(|p| p.into_inner());
    let handle = router.claim_mcu(label);
    let raw = handle.raw();
    self.mcus.lock().unwrap_or_else(|p| p.into_inner()).insert(
        raw,
        McuConnection {
            label: label.to_owned(),
            serial_path: String::new(),
            baud: 0,
            host_io: None,
            runtime_rx: None,
            runtime_caps: None,
            identify_caps: 0,
            kalico_native_supported: true, // EtherCAT endpoint speaks kalico-native
            clock_sync_stop: None,
            clock_sync_thread: None,
            ethercat_socket: Some(socket_path.to_owned()),
        },
    );
    Ok(raw)
}
```
